# Chemical Analysis Pipeline

Analysis pipeline for evaluating de novo UV-filter candidates generated by three ACEGEN-based strategies (REINFORCE, Hill Climb, No-RL baseline). Takes raw generated SMILES + scores as input and produces every table and figure used in the accompanying thesis: validity/uniqueness metrics, descriptor distributions, primary-reward statistics, Pareto/hypervolume multi-objective analysis, bootstrap significance testing, Random Forest feature-importance and y-scrambling validation, external QSAR validation against experimental ECHA data, and chemical diversity/novelty analysis.

## Requirements

- Python 3.10 (matches the HPC venv this was developed against; other 3.10+ versions likely work but haven't been tested)
- RDKit (see note on system dependencies below)

```bash
pip install -r requirements.txt
```

`requirements.txt`:
```
pandas
numpy
rdkit
scikit-learn
scipy
matplotlib
tqdm
requests
```

### A note on RDKit's `Draw` submodule

Figure generation for the top-molecules structure grid (`novelty_check.py`, `src/analysis/plots.py: plot_top_molecules_grid`) uses RDKit's `Draw` submodule, which depends on a system-level 2D rendering library (`libXrender`) that isn't always present on headless servers/HPC. The rest of the pipeline runs fine without it — if this specific figure fails to generate, you'll see a clear warning rather than a crash. Fixes, in order of preference:
- Install RDKit via `conda-forge` instead of `pip` (its build correctly declares this dependency)
- On an HPC system, check for an available X11/Mesa module (`module spider X11`)
- Add `libxrender1` to your container/environment manually

## Configuration

Before running, edit the paths at the top of `config.py`:

| Variable | What it should point to |
|---|---|
| `VENV_PATH` | Your Python virtual environment |
| `ACEGEN_PATH` | Your local ACEGEN installation (see `acegen_scripts/README.md`) |
| `UV_FILTER_PATH` | The `uv_filter.py` scoring function inside your ACEGEN install |
| `PROJECT_ROOT` | This repo's `chemical_analysis/` directory |
| `DATASETS` | Paths to each method's generated-molecules CSV (`compoundsRL.csv`, `compoundsHC.csv`, `compoundsNORL.csv`) |
| `ECHA_REFERENCE_PATH` | The external validation reference CSV (regulator-approved UV filters with experimental λmax/OS) |

**Note**: the No-RL generation script (`prior_sample.py`, in `acegen_scripts/`) writes its output as `prior_only_smiles.csv` by default — rename this (or update `DATASETS["NO-RL"]` in `config.py`) to match whichever filename you configure.

Modelling/statistical hyperparameters (random forest size, CV folds, bootstrap iterations, y-scrambling iterations, etc.) are also centralised in `config.py` — see the comments there for what each controls.

## Running

```bash
python main.py
```

This runs the full pipeline end-to-end: loads/validates the three input datasets, computes descriptors and Lmax/OS predictions (cached — see below), builds objectives, runs the primary-reward and multi-objective statistical analyses, trains and validates the Random Forest / y-scrambling reward-mechanism check, runs external QSAR validation against the ECHA reference set, computes diversity/novelty metrics, and saves every table (CSV) and figure (PNG).

Outputs land in:
- `outputs/tables/` — every results table as CSV (plus a couple of JSON summaries, e.g. `y_scrambling_summary.json`)
- `outputs/figures/` — every figure as PNG

### Caching

The expensive dataset-build step (SMILES canonicalisation, descriptor calculation, Lmax/OS prediction) is cached to `cache/` and keyed against `PIPELINE_VERSION` in `config.py`. If you change anything upstream of the cached step (e.g. edit `processing.py` or `descriptors.py`), bump `PIPELINE_VERSION` so the cache correctly invalidates rather than silently serving stale results. Re-running after only changing downstream analysis code (e.g. adding a new statistical test) will skip straight to the fast part.

### Standalone scripts

Two additional pieces can be run independently of the main pipeline:
- `src/validate_uv_filter.py` — external validation against the ECHA reference set only (`python -m src.validate_uv_filter`)
- `src/novelty_check.py` — PubChem novelty lookup for the top molecules only (`python -m src.novelty_check`); note this makes live network calls (rate-limited) and will report failed lookups distinctly from confirmed-known/novel results rather than silently miscounting them

## Reproducibility

All stochastic steps (train/test splits, cross-validation folds, bootstrap resampling, y-scrambling permutations) use a fixed `RANDOM_STATE` (set in `config.py`, default 42), so a full re-run should reproduce the thesis's reported numbers exactly, given the same input data.
